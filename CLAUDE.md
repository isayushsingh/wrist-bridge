# CLAUDE.md — WristBridge

Context for Claude Code. Read this first, then `docs/01-architecture.md` when you need the design.

## What this project is

**WristBridge** turns any PWA into a native Apple Watch app using **server-driven UI**:

```
Watch app (SwiftUI)  ──HTTPS, x-bridge-key──▶  Proxy (Next.js on Vercel)  ──same-origin HTTPS──▶  PWA
   renders WatchUI JSON                          watch.json + template → sanitize           JSON API + watch.json
```

- `proxy/`: Next.js 16 App Router, TypeScript (strict), route handlers only (plus `/preview` and `/demo` pages). Contains a demo PWA under `/demo`.
- `watch/`: SwiftUI watchOS 10+ app + WidgetKit complication. The project is **generated by XcodeGen** from `watch/project.yml`.
- `schema/`: JSON Schemas (the contract) + `examples/` (real proxy output).
- `docs/`: human docs. Diagrams are in `docs/diagrams/src/*.mmd` (Mermaid source) with rendered `.svg`/`.png`.

The owner is a web developer (Next.js/React/Tailwind/Vercel) who is newer to Swift. When you change Swift code, explain **why** in plain words.

## Commands

```bash
# proxy
cd proxy
npm install
npm run dev                 # http://localhost:3000  (/preview = browser watch renderer)
npm run typecheck           # tsc --noEmit
npm test                    # vitest: template, sanitize, security, full pipeline vs JSON Schema
npm run build               # next build
BASE=http://localhost:3000 KEY= npm run smoke          # smoke test a running server
BASE=http://localhost:3000 node scripts/gen-examples.mjs   # refresh schema/examples

# watch
cd watch
xcodegen generate           # after ANY change to project.yml or adding/removing Swift files
open WristBridge.xcodeproj
```

Always run `npm run typecheck && npm test` after proxy changes.

## Rules and conventions

1. **The WatchUI schema lives in six places; keep them in sync** (see `docs/09-extending.md`): JSON Schema → `watchui.ts` → `sanitize.ts` → `WatchPreview.tsx` → `WatchUI.swift` → Swift component + `NodeView`. A change to one without the others is a bug.
2. **Never fetch from the proxy except via `fetchAppJSON`/`getAppJSON`** (`lib/http.ts`). The same-origin check is a security boundary; don't add bypasses.
3. **Interpolate URLs with `interpolateUrl`** (it URL-encodes), never with `interpolate`.
4. **Sanitize, don't throw**, for content problems: drop the node and push a warning. Throw `BridgeError`s only for request-level failures.
5. Swift decoding must stay **tolerant**: unknown/invalid nodes → `.unsupported`. Never make one bad node fail a document.
6. Don't commit secrets: `proxy/.env*` and `watch/Config/Secrets.xcconfig` are git-ignored.
7. Never hand-edit `.xcodeproj`; edit `watch/project.yml` and regenerate.
8. In `.xcconfig`, write URLs as `https:/$()/host` (`//` is a comment there).
9. Keep payloads small: respect `LIMITS` in `sanitize.ts`; the watch is slow and battery-bound.
10. TypeScript is strict with `noUncheckedIndexedAccess`; no `any`.
11. Docs are part of the change: update `docs/` and diagrams when behaviour changes.

## Gotchas

- Route handler `params` are a **Promise** in Next 15+ (`const { appId } = await params`).
- The in-memory caches (`TTLCache`) are per serverless instance; correctness must not depend on them.
- The demo store resets on restart/cold start, which is expected.
- Vercel *Deployment Protection* on preview URLs blocks the proxy calling its own `/demo`; use production.
- A real watch can't reach `localhost`; the simulator can.
- Free Apple ID installs expire after 7 days; App Groups aren't available, which is why the widget fetches on its own.
